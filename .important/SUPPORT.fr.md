👉 https://opencollective.com/standarx

### Outil compagnon payant optionnel (peut-être, un jour)

Le focus reste le Core open-source. Tant que Standardoc n'a pas de
composant cloud/serveur qui justifierait une infrastructure récurrente,
il n'y a **aucune raison de proposer un abonnement** — et aucun n'est
prévu.

Si un outil compagnon voit le jour un jour (genre UI façon GitBook locale
qui tourne sur votre machine, sans hébergement), voici ce qui est
verrouillé :

- **Local-only** — tourne sur votre machine, pas de cloud, pas de
  dépendance SaaS.
- **Licence à vie achat unique** — pas d'abonnement, pas de per-seat.
- **Scope tooling** — ne ferme jamais la surface du Core OSS.

Que ça ship ou non dépend de l'adoption du projet et d'une demande user
claire. Le Core lui-même est verrouillé pour passer de FSL-1.1-MIT à
**MIT pur le 26 avril 2028** quoi qu'il arrive.

Si vous voulez signaler de l'intérêt pour un outil compagnon, [ouvrez une discussion](https://github.com/miralabs-tech/standardoc/discussions).

## 🏢 Support commercial

Disponible pour :

- **Language providers custom** — ajout d'un langage hors roadmap pour usage interne.
- **Support intégration payant** — branchement de Standardoc dans du tooling interne custom.
- **Sponsorship entreprise** — développement financé de features que votre org veut prioritaires.
- **Couverture langage sponsorisée** — financement du travail pour amener un langage au support first-class.

Contact via l'email dans [`Cargo.toml`](crates/standardoc-cli/Cargo.toml) `authors`.

## 🚀 Pourquoi ça compte

Votre soutien aide à :

- Construire plus de language providers (Python, Go, Java, Swift, …)
- Améliorer la résolution de bridges cross-language (Tauri, WASM, FFI)
- Étendre la surface d'outils MCP (avec rigueur chirurgicale — voir [VISION L97](#))
- Accélérer les patterns d'intégration agents IA
- Garder le Core entièrement OSS sous FSL-1.1-MIT, à perpétuité
